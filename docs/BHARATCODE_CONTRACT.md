# BharatCode API contract

This file is FlightCheck's reference for what BharatCode's model API documents, and what it does
not. Every rule, mock behaviour and adapter check must trace back to a row here. It is also used as
contract context by `flightcheck explain`.

- Primary source: <https://bharatcode.ai/build>, read on **6 November 2026** (Asia/Kolkata).
- Tags: **[VERIFIED]** read on an official page on 6 Nov 2026 · **[OBSERVED]** seen in a secondary
  source (plausible, not an API guarantee) · **[UNVERIFIED]** not confirmed; must be checked by the
  live probe (Phase 10) before being relied on · **[ASSUMPTION]** planning assumption ·
  **[RECOMMENDATION]** design choice that may be revisited via an ADR.
- Rule IDs (`FC-BC-*`, `FC-GEN-*`, `FC-SEC-*`), runtime check IDs (`FC-RT-*`), scenarios (`S01`…)
  and probes (`P-01`…) in §15.2 are FlightCheck's own identifiers; they are introduced in later
  phases.
- The section below is copied verbatim from the implementation plan (§15). Links of the form
  `§NN` point into that plan, which is kept locally and is not part of this repository (see
  ADR-000); this file is meant to be complete without it.
- Keep [UNVERIFIED] labels until Phase 10 replaces them with probe results (with dates).

## 15. BharatCode integration specification

### 15.1 Verified facts from official documentation

Source: <https://bharatcode.ai/build>, read 6 Nov 2026. Everything in this table is **[VERIFIED]** unless stated.

| Topic                             | Documented behaviour                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Base URL                          | `https://bharatcode.ai/api/model/v1`                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Authentication                    | `Authorization: Bearer <BHARATCODE_API_KEY>`; developer key obtained at <https://bharatcode.ai/account>; keep it server-side, never in browser bundles or mobile apps                                                                                                                                                                                                                                                                                                                                      |
| Key format                        | Example placeholder is `bc_live_your_key_here` **[OBSERVED** in an example only; treat `bc_live_` as the likely prefix, confirm when a real key is issued**]**                                                                                                                                                                                                                                                                                                                                             |
| Payloads                          | "OpenAI-compatible Chat Completions or Responses"                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Endpoints                         | `POST /responses`, `POST /chat/completions`, `GET /models` (lists models eligible for your key)                                                                                                                                                                                                                                                                                                                                                                                                            |
| Models                            | `qwen-3.8-27b` (coding, reasoning, images, tool use; `/responses` and `/chat/completions`; Students 10M tokens/day, Lite, Pro). `deepseek-v4.1-flash` (coding, long-context reasoning, images, tool use; both endpoints; **Pro only**)                                                                                                                                                                                                                                                                     |
| Access                            | API access requires Lite, Pro, or verified student access. Lite and Pro have no daily/weekly token allowance. All requests share capacity, may queue, and remain subject to context, output and queue limits                                                                                                                                                                                                                                                                                               |
| `model` field                     | Required on every request                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Responses — input                 | Text or message array, optional `instructions`; use `store:false`; read text and function calls from the `output` array                                                                                                                                                                                                                                                                                                                                                                                    |
| Responses — statelessness         | Stateless: replay history and function-call outputs in `input`                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Responses — supported             | Text and image input, streaming, own function tools, structured output through `text.format`                                                                                                                                                                                                                                                                                                                                                                                                               |
| Responses — unsupported (→ `400`) | `store:true`, `previous_response_id`, hosted tools, background jobs, audio/video/file input                                                                                                                                                                                                                                                                                                                                                                                                                |
| Responses — streaming             | `stream:true` → SSE. Text in `response.output_text.delta`; finish on `response.completed` or `response.incomplete`; `response.failed` is an error; queue keepalive comments are not model output                                                                                                                                                                                                                                                                                                           |
| Truncation (Responses)            | `status:"incomplete"` with `incomplete_details.reason:"max_output_tokens"` means output was cut short even with HTTP 200; the budget includes reasoning                                                                                                                                                                                                                                                                                                                                                    |
| Truncation (Chat)                 | `finish_reason:"length"` means the output budget was exhausted even with HTTP 200                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Handling truncation               | Preserve partial output; do not execute incomplete tool calls; raise `max_output_tokens` / `max_tokens` (up to 32 000) or use `reasoning:{effort:"none"}` / `reasoning_effort:"none"` for short answers; do not automatically retry the same exhausted budget                                                                                                                                                                                                                                              |
| Function tools (Responses)        | Define with `name` and `parameters` (example: `{"type":"function","name":...,"description":...,"parameters":{...,"additionalProperties":false},"strict":true}`, `tool_choice:{"type":"function","name":...}`). The application validates arguments and executes; BharatCode does not run tools. Next request: original input + the `response.output` items + a `function_call_output` item with the matching `call_id` and a **string** `output`. Keep `store:false`; resend tool definitions still needed |
| Busy                              | `503` = model busy: wait a few seconds and retry. A stream that has already started ends with `response.failed` instead                                                                                                                                                                                                                                                                                                                                                                                    |
| Support                           | Include the `x-request-id` response header when reporting a problem                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| OpenAI SDK                        | Point the SDK at the base URL (example shows the JS SDK with `baseURL`; the Python SDK equivalent `base_url=` is standard SDK behaviour **[VERIFIED in SDK README]**)                                                                                                                                                                                                                                                                                                                                      |
